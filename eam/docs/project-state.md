# 프로젝트 현황과 요구사항

갱신: 2026-09-10. 이 문서를 현재 목표·결정·남은 작업의 기준으로 사용한다. 상세 증거는 연결된 실험 기록에 보관한다. 사용자가 아이디어를 제시하면 출처와 상태를 추가하며, 제안·구현·검증을 구분한다. 새로운 아이디어가 기존 목표를 자동으로 대체하지는 않는다.

## 목표와 현재 단계

목표: macOS의 Emacs for Mac OS X에서 Claude Code와 Codex를 기존 구독 계정으로 사용하는 독립적인 AI 개발 환경. 프로젝트는 `~/workspace/emacs-ai`. 개인 Emacs 설정은 수정하지 않고 별도 로드한다.

현재는 **로컬 패키지 0.1.1을 별도 프로필에 설치·검증해 사용자가 직접 테스트할 수 있도록 준비한 단계**다. 두 CLI의 실제 개발 흐름과 배치 장시간 검사는 완료했으며, 일상 GUI·물리 IME·GUI 부하 반응은 사용자 테스트와 함께 이어간다. 일상 개발 도구 전체가 완성됐다고 판단하지 않는다. 현재 진행 방향은 **Ghostel의 대화형 CLI를 기본으로 사용하고, 필요할 때 일반 Emacs 버퍼로 입력을 편집**하는 방식이다. 가짜 생성기와 JSON 어댑터는 비교·회귀 검증용으로 유지한다. 항목별 현재 판단은 [요구사항 대조표](completion-audit.md), 작업 순서는 [실행 계획](execution-plan.md)을 따른다.

## 결정과 보류

- **현재 방향:** 공식 CLI의 대화형 기능과 프로세스를 유지한다. 앱은 세션 접근·입력 편집·기록을 돕는다.
- **입력 기본값:** 터미널 직접 입력. 긴 편집은 외부 편집기 왕복, 별도 새 초안은 필요할 때 연다.
- **검증 정책:** GUI/IME, 실제 CLI의 PTY 배치, 가짜 프로토콜/출력 테스트를 같은 성공으로 합치지 않는다.
- **참고 도구:** Orca는 `stablyai/orca`를 가정했다. 사용자에게 다른 저장소가 제시되면 비교 대상을 수정한다.
- **보류:** 전체 도구 승인 UI를 JSON 어댑터에 별도로 재구현하는 일은 현재 우선 경로가 아니다. 대화형 CLI의 승인을 사용하는 흐름부터 검증한다.
- **미결:** Ghostel 직접 한글 조합의 세부 관찰, 최신 GUI의 세션 재개·검색 사용성, 장시간 GUI 반응. vterm 비교는 Ghostel 결함이나 사용자 요청이 있을 때 진행한다. 기록 검색·제한 페이지는 구현했으며 ANSI 화면 전체 복원은 범위에 넣지 않았다.
- **사용자 관찰:** 앞선 GUI에 “별 문제 없는 것 같아”라는 보고가 있었고, 2026-09-08에는 “잘 되는 것 같은데”라는 추가 관찰을 받았다. 기본 사용에 대한 긍정적 관찰로 기록한다. 입력기 종류·조합/삭제·메뉴 전환 등 개별 시험 결과는 명시되지 않아 전체 IME 체크리스트 통과로 확대하지 않는다. 앞선 “아마 될 거라고 믿어”도 실제 시험 통과로 기록하지 않는다.

이 문서는 대화의 모든 문장을 전사하는 로그가 아니다. 요구·결정·이유·상태와 증거를 남긴다. 앞으로 새 기능/아이디어는 R 번호로 추가하고, 단순 아이디어는 ‘제안’, 합의된 방향은 ‘결정’, 코드는 ‘구현’, 시험 근거가 있는 범위만 ‘검증’으로 표시한다. 기존 판단이 바뀌면 이전 이유도 간단히 남긴다. 사용자는 특별한 양식 없이 아이디어를 전달해도 된다.
