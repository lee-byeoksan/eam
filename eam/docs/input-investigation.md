# 자동 입력 원인 분리와 수정 — 2026-09-08

이 기록은 [이전 GUI 검증](validation.md)의 한글 입력 판정 보류와 live 헤더 문제에 대한 후속 결과다. 실제 키보드 확인은 [복귀 후 절차](keyboard-handoff.md)에 분리했다.

## 수정한 내용

- live 헤더가 최초 바이트 범위에 머물던 문제를 수정했다. 매 출력 배치의 디스크 기록 후 **저장된 전체 바이트**와 **현재 출력 문자 수**를 각각 표시한다. 한글·이모지 바이트 수와 문자 수를 혼동하지 않는다.
- 과거 페이지 헤더는 해당 조회 구간을 고정해서 표시한다. 최신 보기로 돌아오면 저장 바이트를 다시 읽는다.
- 제품에 `AI` 메뉴를 추가하여 전송·중지·기록 이동을 키보드 단축키 없이도 실행할 수 있게 했다. GUI에서 실제 메뉴 전송과 중지를 확인했다.
- 테스트 전용 A/B 비교 화면, 제한된 이벤트 추적, 명시적 결과 저장, 복귀용 실행 스크립트를 추가했다. 개인 Emacs 설정은 변경하지 않았다.

제품에는 입력기 교체, 전역 키 변환, 임의의 한글 단축키 매핑을 추가하지 않았다.

## 비교 방법

같은 격리 Emacs GUI 안에서 A는 일반 `text-mode`, B는 `emacs-ai-input-mode`로 만들었다. 매 실험마다 새 빈 입력 쌍을 사용했다. A/B 입력창과 한 개의 출력창을 함께 표시하고, 나머지 스트림은 백그라운드에서 실행했다. 비교 버퍼에만 최근 100개 명령 이벤트를 기록했다.

개별 키 비교는 `k → f → s → Backspace → s → Space`, 짧은 연속 비교는 `k f s Space`를 다섯 번 보냈다. 입력 소스를 임의로 변경하지 않았고, 실제 도착한 Unicode 코드포인트와 Emacs 명령을 비교했다. 이 키 이름은 자동 도구의 키 이름이며 사용자가 따라 칠 한글 타자법을 뜻하지 않는다.

`ns-insert-working-text`에 테스트용 관찰 함수를 붙여 네이티브 working-text 경로가 호출되는지도 확인했다. 이 추적은 테스트 앱에만 있고 제품 코드에는 없다. 마지막 재실험의 스냅샷은 관찰 함수가 실제 설치됐는지도 명시한다.

## 결과

| 시험 | A: text-mode | B: 프로토타입 | 해석 |
| --- | --- | --- | --- |
| 개별 키 + Backspace, 무부하 | `간 ` | 동일 | 차이 없음 |
| 개별 키 + Backspace, 1스트림 | `간 ` | 동일 | 차이 없음 |
| 개별 키 + Backspace, 12스트림 | `간 ` | 동일 | 차이 없음 |
| 짧은 연속 키, 무부하 | `간 ` × 5 | 동일 | 누락 재현 못함 |
| 짧은 연속 키, 12스트림 | `간 ` × 5 | 동일 | 누락 재현 못함 |
| `type_text("한글ABC🙂")` | 한글 삽입 실패, 예상치 않은 Meta 명령 발생 | 삽입 실패 | 정상 입력 시험으로 사용 불가 |
| 기본 `sky.paste` | 빈 문자열, timeout | 빈 문자열, timeout | 양쪽에 동일한 잘못된 키 도착 |
| 진단용 임시 매핑 후 `sky.paste` | `한글 붙여넣기 🙂` 정확히 삽입 | 동일 | 도구는 여전히 timeout 보고 |

개별 키의 결과는 완성형 `간`(U+AC04) 한 글자가 아니라 **U+1100, U+1161, U+11AB, U+0020**이었다. 앞의 세 문자가 글꼴에서 `간`처럼 함께 표시된다. 로그에서는 각 자모가 `self-insert-command`로 들어오고, Backspace는 `delete-backward-char`로 마지막 자모를 지웠다. 추적 설치를 확인한 재실험에서도 native working-text 이벤트는 0회였다.

따라서 이전에 관찰한 “간→가”만으로 macOS 네이티브 IME의 조합 중 삭제를 검증했다고 할 수 없다. 확인한 것은 도구가 전달한 분해형 자모에 대한 버퍼 편집 동작이다. 프로토타입만의 키 누락이나 부하에 따른 차이는 이번 통제 비교에서 재현하지 못했다. 실제 사람의 입력 속도·조합·후보창에 대해서는 결론을 내리지 않는다.

## TextEdit 대조와 붙여넣기 원인

별도로 만든 빈 TextEdit 문서에서도 같은 `type_text("한글ABC🙂")` 호출의 결과는 **`ABC`**였다. 반면 TextEdit의 `sky.paste("한글 붙여넣기 🙂")`는 정상 동작했다. 적어도 완성형 문자열 자동 입력 누락은 이 프로토타입에만 있는 현상이 아니다. 앱별 실제 입력 소스까지 강제로 통일한 시험은 아니므로 OS 전체 원인을 확정한 결과로 해석하지 않는다.

Emacs A/B에서 기본 paste가 보낸 이벤트는 둘 다 **8393065 = Super + U+1169 (`ᅩ`)**였다. 기대한 `Super+v`가 아니므로 바인딩이 없었고 클립보드를 읽지 않았다. `type_text`에서는 일부 입력이 Meta 명령으로 도착해 `shell-command` 프롬프트까지 열렸다. 셸 명령 내용을 입력해 실행하는 시험은 하지 않았다.

이벤트 전달 원인을 확인하기 위해 **현재 비교 쌍에만** 관찰된 8393065 이벤트를 `clipboard-yank`에 연결했다. 이후 양쪽 모두 한글·이모지를 정확히 읽어 삽입했지만, Computer Use는 여전히 클립보드 읽기 timeout을 반환했다. 즉, 다음 두 현상을 구분해야 한다.

1. 자동 키 이벤트가 Emacs에서 기대한 단축키와 다르게 해석된다.
2. 실제 붙여넣기에 성공해도 도구의 완료 감지가 실패할 수 있다.

이 임시 매핑은 제품에 넣지 않았고, 복귀용 새 A/B 쌍에는 적용되지 않는다. 사용자 키보드의 `Command+V`도 같은 문제인지 여부는 아직 미검증이며, `Edit → Paste`와 함께 직접 비교하도록 준비했다.

TextEdit 대조용 합성 문서는 프로젝트 `var/textedit-control.rtf`에 보관했다. 별도 테스트로 실행했던 TextEdit 프로세스는 종료했다. 기존 개인 Emacs는 조작하지 않았다.

## 수정 후 자동 검사와 측정

최종 ERT **6/6 통과**, 제품과 GUI 테스트 도우미 byte compile 경고 없음, 셸 구문과 Python 구문 검사 통과.

새 회귀 테스트는 `한🙂` 기록 후 7바이트·2문자, 200자 한글 추가 후 607바이트·128문자 상한, history 헤더 고정, live 복귀 시 610바이트 갱신을 확인한다. 기존 기록 무손실·페이지 상한·undo·세션 격리·디스크 오류 검증도 통과했다.

헤더 갱신의 비용을 포함해 [기존 벤치마크를 다시 실행](benchmark-after-header.json)했다.

| 세션 | 출력 문자 합 (100→1,000배치/세션) | 배치 p95 / 최대 ms |
| --- | ---: | ---: |
| 1 | 65,536 → 65,536 | 0.273 / 6.710 |
| 4 | 262,144 → 262,144 | 0.296 / 7.084 |
| 12 | 786,432 → 786,432 | 0.278 / 16.083 |

12세션, 세션당 과거 조회 1,000→5,000회 후 RSS는 **98,720→99,856KiB**, GC live 객체 추정치는 **1,222,478→1,222,630바이트**였다. 3초 batch heartbeat 최대 간격 초과는 **63.81ms**였다. 이는 실제 GUI 키 입력 지연이 아니며, 이전 결과와의 단일 실행 차이를 성능 개선·악화로 단정하지 않는다. 동시 GUI 시험과 OS 부하도 통제하지 않았다.

## 증거와 남은 일

원시 [A/B 스냅샷 9개](gui-evidence/ime-comparison.jsonl)는 순서대로 개별 키 무부하·1스트림·12스트림, 완성형 입력 실패, 기본 paste 실패, 진단 paste, native 추적 확인 재실험, 연속 키 무부하·12스트림이다. 키 이벤트·모드·원문·코드포인트를 포함한다.

[12스트림 A/B 화면](gui-evidence/paired-12-streams.png), [진단 paste 화면](gui-evidence/paste-diagnostic.png), [TextEdit 대조](gui-evidence/textedit-control.png), [수정된 live 헤더](gui-evidence/live-header-fixed.png)를 보관했다.

사용자가 필요한 항목은 실제 키보드의 macOS 한글 조합·한/영 전환·undo·Command+V와 체감 지연이다. [복귀 후 절차](keyboard-handoff.md)와 빈 비교 화면을 준비했다. 실제 AI 연결이나 인증 변경은 수행하지 않았다.
