# 최신 코드 장시간 측정

2026-09-09 G08, 1시간 배치 검사 완료(런처 종료 코드 0). 두 가짜 PTY로 현재 제품의 출력 기록·입력 전달·제한 페이지를 검사하며, **배치 검사**다. 실제 CLI·GUI·물리 IME 반응 측정은 아니다.

이전 1시간 결과의 후반 footprint 증가가 종료 후 회수되는지 확인하기 위해 `tests/terminal-stream-soak.el`에 정리 전·세션 종료 직후·GC 후의 proc_pid_rusage 계측을 추가했다. 샘플러 실패가 세션 정리를 막지 않도록 unwind-protect로 분리했다. `run-stream-soak.py`는 모든 제품 Lisp 소스 해시를 보관하고 세 단계 계측·세션 0개를 확인한다.

5초 사전 검사 `var/soak-cleanup-smoke-20260909`는 성공했다. 기록 해시 2개 일치·페이지 16개 상한 통과, footprint는 정리 전 48,235,432B에서 GC 후 46,498,728B였다. 이는 짧은 검사이며 장시간 증가의 해명을 대신하지 않는다.

본 검사 명령: `python3 tests/run-stream-soak.py var/soak-latest-1h-20260909 --seconds 3600`. 런처 세션 59910으로 실행했으며 Emacs PID는 출력 디렉터리의 `emacs.pid`, 시작 조건·코드 해시는 `manifest.json`, 실시간 누적 표본은 `samples.json`/`footprint.jsonl`에 있다. 세션 번호·PID 파일만으로 생존을 판단하지 않고 런처 핸들과 갱신되는 표본을 확인한다. 관찰 타임아웃만으로 재시작하지 않는다.

`analysis.json`·`cleanup.jsonl`·런처 종료 코드 0을 함께 확인했다. 분석기는 생산자 해시·바이트 수·입력 수신·undo 상태·과거 페이지 상한을 검증했다. 아래는 이번 실행 범위의 결과이며 무누수 증명은 아니다.

실행 중 기록 검색의 입력 전송 실패 정리를 별도로 수정했다. 본 스트림 검사는 검색 작업을 실행하지 않으며, 그 변경은 별도 history ERT 2개로 검증했다. 본 검사의 코드 기준은 시작 시 manifest 해시다. 작업 트리 전체가 종료 시점에도 같은 해시라고 주장하지 않는다.

이번 결과는 이전 검사의 후반 증가를 동일하게 재현하지 않았고, 종료 후 일부 회수를 직접 확인했다. 현재 증거만으로 메모리 수정이나 무조건적인 추가 장시간 반복을 결정하지 않는다. 다음 G08 검증은 실제 GUI의 부하 중 입력·스크롤·세션 전환 지연이다. 실제 Claude/Codex 메모리, 한글 조합, 화면 렌더링 반응은 이번 검사에 포함되지 않았다. 약 40분 시점의 별도 자동 회귀 실행과 시간이 겹친 점도 고려해야 한다.
