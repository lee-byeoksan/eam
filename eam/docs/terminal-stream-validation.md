# 10분 PTY 출력·입력·기록 검증

2026-09-08. 같은 배치 Emacs에서 Python 가짜 출력 생성기 두 개를 **실제 PTY**로 연결해 600.1초 실행했다. AI 호출과 네트워크는 없으며, 기존 필터에 문자열을 직접 주입한 벤치마크와 구분한다. GUI·물리 키보드 IME 검사는 아니다.

## 데이터와 검사 방법

각 생성기는 한글·이모지·코드 모양 문자열·ANSI 색상을 포함하는 로그를 출력했다. 약 25ms 간격의 입력 대기 시간을 두고, 100회마다 18KB 정도의 긴 줄도 출력했다. 실제 처리량은 Emacs가 PTY를 읽는 속도와 입력 수신에 영향을 받는다. 임의의 일정 MB/s 처리량을 보장하는 시험이 아니다.

생성기는 `os.write`가 실제로 쓴 모든 바이트를 누적 SHA256으로 계산했다. 앱의 전체 ANSI 기록은 끝에서 별도 스트리밍 해시로 대조했다. Ghostel의 exec 래퍼가 출력하는 시작 화면 지우기 `ESC[H ESC[2J` 7바이트를 정확히 확인한 뒤, 나머지 전부가 생성기 바이트 수와 해시에 일치하는지 검사했다. 임의의 시작/끝 부분을 제외하여 통과시킨 것이 아니다. 두 세션 모두 일치했다.

약 30초마다 Emacs 초안 버퍼의 `한글-ping-…` 문자열을 bracketed paste로 전송했다. Enter는 보내지 않았다. 생성기가 받은 정확한 문자열과 수신 시각을 파일에 기록하여 40개 입력을 대조했다. 입력 undo 활성·출력 undo 비활성 상태도 모든 표본에서 확인했다. 이 시험에서는 실제 undo 동작을 반복하지 않았으며 그 동작은 앞선 PTY ERT에서 검사했다.

## 결과

| 세션 | 원시 기록 바이트 | 최대 출력 버퍼 문자 | 입력 수신 | 입력 수신 시간 중앙값 / 최대 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 45,947,686 | 74,572 | 20 | 4.02 / 8.99 |
| 0 | 48,394,427 | 74,705 | 20 | 0.47 / 21.86 |

두 파일 합계 **94,342,113바이트(약 90.0 MiB)**를 보존했다. 출력 버퍼는 관찰 범위에서 최대 74,705문자였다. Ghostel의 스크롤백은 128 KiB 엔진 예산이므로 일반 버퍼 프로토타입의 65,536문자 상한과 같은 값이 아니다. 전체 기록은 계속 증가했지만 표시 버퍼가 기록 전체를 누적하지 않는 것을 확인했다.

Emacs RSS는 첫 표본 51.6 MiB → 마지막 93.2 MiB, 최대 97.0 MiB였다. 첫 표본은 시작 약 2초 시점으로 워밍업 이후 기준선이 아니다. 300초 이후 RSS 범위는 92.9–97.0 MiB였다. 초기 증가가 있으며 이 시험만으로 누수 없음이나 장시간 고정 메모리를 보증하지 않는다. RSS는 호스트 Emacs 값이며 생성기 프로세스 메모리는 포함하지 않는다.

입력 시간은 Emacs가 초안 전송을 시작한 시각부터 생성기가 수신한 시각까지다. Emacs 파일 기록, PTY 전달, 생성기의 입력 대기가 포함된다. GUI redisplay·IME·사용자가 느끼는 응답 시간을 측정한 값은 아니다. 동시에 다른 배치 Emacs에서 실제 CLI 종료 시험도 수행했으므로 시스템 부하가 완전히 통제된 비교 벤치마크는 아니다.

출력 완료 후 각 ANSI 파일을 제한 페이지 뷰어로 열고 이전 페이지를 8번씩 불러왔다. 상한 4,096문자에 대해 검사한 16페이지 모두 통과했고, 최대 실제 페이지는 2,678문자였다. UTF-8 바이트 단위 읽기 때문에 문자 수는 상한보다 작을 수 있다. 전체 파일을 한 번에 버퍼로 읽지 않았다. 모든 과거 페이지를 순회하거나 ANSI 화면을 재생한 것은 아니다.

## 재현

```sh
EMACS_AI_STREAM_DIR="$PWD/var/새로운-stream-시험경로" \
EMACS_AI_STREAM_SECONDS=600 \
  /Applications/Emacs.app/Contents/MacOS/Emacs --batch -Q -L lisp \
  -l tests/terminal-stream-soak.el
python3 tests/analyze-stream-soak.py var/새로운-stream-시험경로
```

`tests/stream-fixture.py`가 생성·수신 검사를 담당한다. 로컬 Unix 서버 소켓과 프로세스 RSS 조회가 허용되는 환경이 필요하다. 먼저 5초 예비 시험을 완료했고, 긴 실행은 10분 한 번 수행했다. 각 실행 기록은 분리했다. 전체 ANSI는 `var/terminal-*.ansi`, 생성기 예상 해시·수신 기록은 선택한 시험 디렉터리에 보존한다. 진단 코드의 Python 컴파일 및 Lisp 괄호 검사도 통과했다.
