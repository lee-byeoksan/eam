# 프로젝트 실행 명령 — F05

2026-09-10 구현·설치 검증. 0.6.1 패키지에 포함됐다.

| 동작 | 명령 | 키 |
|---|---|---|
| 등록·같은 이름 교체 | `emacs-ai-task-register` | `C-c a T a` |
| 프로젝트의 명령 선택·실행 | `emacs-ai-task-run` | `C-c a T r` |
| 현재 명령의 전체 기록 | `emacs-ai-task-output` | `C-c a T o` 또는 실행 버퍼 `C-c C-o` |
| 현재 명령 새 실행 | `emacs-ai-task-rerun` | 실행 버퍼 `g` |
| 실행 취소 | `kill-compilation` | 실행 버퍼 `C-c C-k` |

`T`는 대문자다. 디렉터리·이름·shell 명령을 사용자가 직접 등록한다.
등록과 조회는 실행하지 않는다. 실행 명령을 고르면 해당 프로젝트를 cwd로 삼아
compilation 버퍼를 새로 연다. 명령 자체는 사용자가 작성한 shell 코드이므로
명령이 AI CLI를 호출하는 경우까지 AI 호출이 없다고 보장하지 않는다.
앱은 결과를 AI 세션에 자동 전달하지 않는다.

등록은 `emacs-ai-directory/project-commands.json`의 버전 1 데이터로 보관한다.
프로젝트는 정규화된 실제 경로로 구분한다. 최대 1 MiB이며 임시 파일에서 원자적으로
교체한다. 등록은 공용 잠금 디렉터리를 먼저 획득한 뒤 읽기·변경·쓰기를 수행한다.
다른 등록이 잠금을 갖고 있으면 덮어쓰지 않고 거절한다. 강제 종료로 남은 잠금은
자동 삭제하지 않으므로 등록 중인 프로세스가 없는지 확인한 뒤 정리해야 한다.

실행 로그는 `emacs-ai-directory/commands/output-*.log`다. 받은 UTF-8 텍스트
출력을 모두 기록하며, 버퍼와 갱신 대기 텍스트는 `emacs-ai-task-buffer-limit`
기본 65,536자만 유지한다. 화면 갱신은 50ms 단위로 모으고 output undo는 끈다.
잘린 오래된 오류 위치는 현재 compilation 버퍼에서 탐색할 수 없지만 전체 기록은
제한된 페이지로 다시 열 수 있다. `g`는 별도 로그를 갖는 새 실행을 만든다.

## 검증과 남은 작업

`tests/tasks-test.el` 3개 통과: 프로젝트별 명령 분리·재등록·등록 중 미실행,
실제 shell cwd와 종료 코드 7, 5,000줄 한글 출력의 전체 디스크 보관과 실행 중
512자 버퍼·대기 문자열 제한, output undo 비활성화, sleep 명령 취소.
앱 회귀 15개 통과. 실제 AI는 실행하지 않았다.

재실행, 기록 실패, 빠른 프로세스 시작/종료의 출력 보존, 설치본과 GUI 검증은
남아 있다. 이 단계의 제한 보장은 앱의 실행 경로를 대상으로 하며, 임의의
`M-x compile` 또는 `M-x recompile` 실행은 앱의 기록 경로를 사용하지 않는다.
취소는 Emacs compilation 프로세스에 요청하며 외부로 분리된 daemon을 모두
종료하는 기능은 아니다.

## 수명·실패·재실행 검증 보완

[배치 로그](evidence/tasks/lifecycle.log): 8개 통과. 앱 회귀 15개도 통과했다.

- compilation 시작 훅 안에서 출력을 처리하도록 시험해도 빠른 한글 출력이
  디스크에 모두 남았다. `g` 재실행은 원래 명령 이름·cwd를 유지하며 새 로그를 만든다.
- 쓰기 실패를 주입하면 해당 프로세스가 종료되고 헤더에 RECORDING ERROR가 남는다.
- 실행 버퍼를 닫으면 native compilation의 진행 목록에서도 프로세스가 제거된다.
- 5,000개 서로 다른 오류 파일 위치를 출력해도 오래된 출력 삭제 후 오류 위치
  캐시가 남아 계속 커지지 않는다. 이 테스트는 장기 RSS 측정과는 별개다.
- 등록 잠금 충돌은 기존 잠금을 건드리지 않고 거절한다. 잘못된 JSON은 덮어쓰지
  않으며 실패 시 이번 등록이 잡은 잠금만 해제한다.

기록 연결은 compilation-start가 반환한 뒤가 아니라 compilation-start-hook에서
설치한다. 종료 알림은 버퍼가 이미 닫힌 경우에도 원래 sentinel로 전달한다.
설치본·GUI·장시간 개발 서버 사용 검증은 아직 남아 있다.

## 개발 서버와 설치본 검증

[HTTP 서버 로그](evidence/tasks/http-server.log): 등록한 명령으로 127.0.0.1의
OS 할당 포트에서 실제 Python 서버를 실행했다. 한글 HTTP 응답, 요청 로그 보관,
취소 후 프로세스·타이머 종료 및 포트 연결 실패를 확인했다. 짧은 수명 통합 시험이며
장시간 서버 soak나 외부로 daemon화한 프로세스 종료를 검증한 결과는 아니다.

실행 중인 프로젝트 명령이 있는 worktree는 삭제를 거절하도록 F04와 연결했다.
AI 세션뿐 아니라 같은 worktree의 프로세스 버퍼도 확인한다. 취소 후에는 깨끗한
worktree를 삭제할 수 있는 실제 Git 회귀 테스트가 통과했다.
