# 추가 기능 검증 현황

2026-09-10, 최신 검증 설치본 0.8.11. **F01–F07 구현 및 검증 완료**이다.
일반 버퍼의 물리 한글 조합·undo와 Codex 지속 세션의 새 GUI 복원·수동 재접속·미제출
입력 보존·편집기 왕복·명시 종료를 사용자가 모두 정상으로 보고했다. 도구 키 전달 장애와 구분한다.
기능 구현·자동 시험·실제 CLI 시험·실제 GUI 시험을 구분한다.

사용자 직접 확인: 0.8.7 시험 GUI에서 ABC 상태의 Esc → x, emacs-ai-help 실행,
q 복귀가 모두 정상이라고 보고했다. 공통 진입·도움말 흐름은 물리 키보드로 확인됐으며,
이 결과를 F01–F07 전체나 물리 한글 조합의 통과로 확대하지 않는다.

추가 실제 GUI 확인: M-x emacs-ai-codex에서 프로젝트 선택 후 Codex v0.154.0 시작,
프로젝트 루트 표시 확인. 새 AI 요청 0회. 단일 후보 선택·전환은 도구로, 여러 긴 한글 경로의 후보·브랜치 구분과 취소는
후속 사용자 직접 시험으로 확인했다. [기록](evidence/gui-087/observations.md).

0.8.10 설치본의 [59개 ERT 및 패키지 수명 검증](evidence/gui-087/package-install-0810.log)은
실행한 요구사항에 대한 근거다. 이 숫자로 미실행한 GUI/실제 AI 작업까지 통과했다고 판단하지 않는다.
실제 CLI의 /model·미제출 입력 편집은 AI 응답을 요청하지 않는 범위였으며,
이후 별도 요청 1회씩으로 두 제공자의 실제 파일 수정을 확인했다. 완료 훅은 실제 출력에서
확인했고, DCS 포장 수신 실패를 수정한 뒤 원본 재생·설치본 가짜 PTY로 검증했다.
실제 요청 결과와 수정 후 재생 검증은 [과거 상세 기록](evidence/persistence/exploration.md)에서 구분한다.

## 완료된 부하 측정

- 0.8.3, 가짜 CLI 4개, 600초. 200초에 2개 분리, 400초에 재접속.
- 설치본의 실제 Ghostel·지속 명령을 사용한다.
- GC 후 Emacs와 소유 CLI 프로세스 트리 전체 RSS를 숫자 PID 관계로 수집한다.
  측정 Python/ps 자체는 제외한다.
- 결과 경로: `var/persistence-soak-600-01/`.
- 같은 실행에서 600초 완료·종료 코드 0 확인. 측정된 25개 PID의 종료 후 부재도 확인했다.
- [과거 표본과 한계](evidence/persistence/exploration.md)에 전체 RSS 및 GC 후 Emacs RSS 증가를 기록했다.
  누수 부재나 GUI 반응성의 증명으로 해석하지 않는다.

## 남은 검증과 진행 방식

화면 조회는 복구됐지만 Computer Use의 키 전달은 간헐적으로 실패한다. 실제 사용자의
M-x·세션 선택·알림 키 확인은 정상이다. 키 전달 실패를 제품 기능 실패로 단정하지 않는다.
[전체 관찰 기록](evidence/gui-087/observations.md)에 각 직접 조작과 초기 fixture를 구분했다.

완료된 GUI 시험(세션 후보·알림·일반 diff 리뷰·worktree 탐색·프로젝트 명령)은 반복 요청하지 않는다.
다음 순서로 남은 범위만 확인한다.

1. worktree GUI 생성과 Magit 영역 선택·리뷰·undo는 직접 확인을 마쳤다.
   Codex 지속 세션의 분리·새 GUI 재접속·편집기 반환도 사용자 확인으로 완료했다.
   Claude도 후속 도구 정상 전달 시 실제 편집·분리·새 GUI attach·편집기 반환·종료를
   확인했다. 0.8.10에서 시작해 새 0.8.11 GUI에서 연결했고 서버 stopped와 기록 보존을
   대조했다. [왕복 기록](evidence/gui-087/observations.md)을 참고한다.
2. 일반 버퍼의 한글 조합·받침 삭제·한영 전환·undo는 사용자 확인으로 완료했다.
   리뷰 의견과 completion 미니버퍼도 사용자 확인 완료다. completion의 Space는
   기본 단어 완성 명령이며, 사용자는 이 동작 외에 한글 입력·수정이 정상이라고 확인했다.
   붙여넣기·도구 type_text는 물리 조합의 대체 근거가 아니다.
   해당 항목은 마지막에 한 번에 모으며 현재 반복 확인을 요청하지 않는다.
3. 선택적 macOS 알림은 기본 꺼짐이다. 별도 alert/osx-notifier 시험에서 사용자 직접
   배너 표시와 백엔드 정상 반환을 확인했다([근거](evidence/gui-087/desktop-probe-user.json)).
   서버 소실 후 자식 프로세스 종료 증명과 삭제 보호 해제는 현재 지원하지 않는다.
   이런 한계를 자동 시험 통과나 문서 정리만으로 해결됐다고 취급하지 않는다.

일반 GUI 스트림 4개에서 출력·상하 스크롤과 125개 표본의 버퍼 상한 65,536자·undo 꺼짐을
확인했다([측정](evidence/gui-087/scroll-summary.json)). 프로젝트 로그의 이전 페이지와
스크롤도 직접 확인했다. 이것은 물리 한글 입력 지연이나 장시간 터미널 반응성을 증명하지 않는다.

현재 시험 실행:

```sh
bash ~/workspace/emacs-ai/var/package-profile-0.8.11/start.sh
```

새 GUI를 여는 명령이며 개인 init을 읽지 않는다. 패키지에 포함된 문서는 빌드 당시
스냅샷이고, 이후 GUI 근거와 사용 안내 정정은 이 작업 폴더의 문서에 먼저 반영된다.
원본 불변 패키지에 후속 문서 변경이 들어갔다고 가정하지 않는다.

0.8.9는 문서·버전 갱신이며 0.8.8과 런타임 소스가 동일함을 비교했다. 설치본 도움말의
누락 명령 7개 포함과 패키지 수명·별도 프로세스 복원을 확인했다. 이번에는 PTY/Magit을
반복하지 않았다. [비교](evidence/gui-087/package-089-audit.json), [실행 로그](evidence/gui-087/package-install-089.log).

최종 대조에서 선택적 데스크톱 전달의 빈 제목이 선택 버퍼명으로 채워질 수 있는 문제를
발견해 0.8.11에서 원래 세션 버퍼를 유지하도록 수정했다. 설치·PTY·Magit 60개 ERT와
패키지 수명 검증이 통과했다([로그](evidence/gui-087/package-install-0811.log)).
현재 프로필의 OS 배너에는 별도 alert 의존성이 없으며 Emacs 메시지로 대체된다는
조건을 안내에 명시했다. 이후 별도 의존성을 로드한 시험 GUI의 OS 배너는 사용자 확인으로 통과했다.

[최종 요구사항 대조](completion-audit.md)에 F01–F07의 근거와 잔여 미검증 범위를 정리했다.
현재 설치본 해시·manifest·제품 Lisp 및 Python bridge 소스의 일치를 확인했다.
마지막 completion 한글 입력·수정도 사용자 확인을 받아 전체 목표를 완료 판정했다.
