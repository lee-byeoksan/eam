# 세션 선택 목록 개선

2026-09-10. cmux·Orca의 세션 메타데이터 표시 아이디어를 참고해 독립 구현했다.

`M-x emacs-ai-app-switch` 또는 키 모드의 `C-c a s`가 버퍼 이름, CLI 종류,
프로젝트 경로, Git 브랜치, 프로세스 상태를 표시한다. 기존 버퍼로만 이동한다.
동일 프로젝트의 여러 세션은 고유 버퍼 이름으로 구분한다.

AI 호출·입력 전송·자동 컨텍스트 삽입·주기적 타이머는 없다. 목록을 여는 동안
각 로컬 프로젝트에서 Git symbolic-ref를 최대 한 번 실행한다. 원격 경로는 조회하지 않는다.
최대 8개를 동시에 실행하며 전체 대기는 기본 2초다. 대기 중 타이머·프로세스 출력을
처리하고 C-g 취소 시 실행한 조회 프로세스를 정리한다. 기한 내 확인하지 못한
브랜치는 `unverified`로 표시하며, 다음 목록 실행에서 다시 조회한다.
`run`은 OS 프로세스 상태이며 AI 작업 완료나 승인 대기 상태가 아니다.

## 검증

`bash scripts/test-app.sh`: 15/15 통과, ERT 보고 실행 시간 약 1.14초.
이는 전체 UI 지연이나 메모리 사용량 측정값이 아니다. 실제 AI는 실행하지 않았다.

- 같은 프로젝트의 두 세션 선택, 죽은 버퍼 제외, 프로젝트별 Git 조회 중복 제거.
- 목록 재실행 시 메타데이터 갱신, CLI 시작 및 입력 전송 경로가 호출되지 않음.
- 실제 임시 Git 저장소의 한글 브랜치(첫 커밋 이전 포함), 저장소 없는 경로,
  사라진 경로, 원격 경로 처리.
- 실제 로컬 셸의 종료 코드와 기록 오류 표시, 빈 목록 오류 처리.
- 기존 앱·키 바인딩·재개 관련 배치 회귀 테스트.

## 한계와 사용자가 확인할 부분

### 다수 프로젝트 기준 측정 (2026-09-10)

`tests/session-selector-benchmark.el`은 임시 로컬 Git 저장소와 출력 없는
세션 버퍼를 만들고, 각 규모에서 목록 생성을 5회 측정한다. AI CLI는 실행하지
않는다. 한글·공백 경로와 한글 브랜치를 포함하며 후보 수와 브랜치 보존도 확인한다.
Emacs 30.1 배치 실행의 [원시 결과](evidence/session-selector/baseline.json):

| 서로 다른 프로젝트 수 | 생성 시간 범위 | 중앙값 |
|---|---|---|
| 1 | 0.012–0.156초 | 0.017초 |
| 10 | 0.459–0.630초 | 0.526초 |
| 30 | 1.280–2.191초 | 1.709초 |
| 100 | 5.821–8.468초 | 7.424초 |

이는 후보 생성 시간이며 GUI 입력 지연이나 completion 렌더링 측정값은 아니다.
수정 전 구현은 프로젝트마다 동기 Git 프로세스를 실행했다. 느린 마운트 디스크는
이 측정에 포함하지 않았다.

이번 GUI 시도는 Computer Use의 `Sky Computer Use native pipe startup failed`로
앱 상태를 얻지 못했다. GUI 시험을 통과로 계산하지 않는다. 독립 시험 앱은
`var/Emacs AI selector.app`에 준비돼 있으며 기존 사용자 창을 재시작하지 않았다.

GUI의 긴 후보 표시, 한글 조합, 사용 중인 completion UI와의 조합은 미검증이다.
프로세스 생성 자체와 경로 접근의 OS 지연은 2초 제한의 엄밀한 실시간 보장이 아니다.
조회 대기 중 일반 편집을 병행하는 UI는 아니며, 목록 표시 전까지 기다리거나 C-g로 취소한다.
브랜치 `—`는 detached HEAD, Git 불가, 저장소 없음 등을 구분하지 않는다.
목록을 열어 둔 사이 발생한 상태 변경은 다시 열어야 반영된다.

소스 실행 `bash ~/workspace/emacs-ai/scripts/start.sh`에서 시험한다.
0.2.1 패키지와 별도 프로필을 준비했다. 기존 0.2.0 프로필과 실행 중인 GUI는
변경하거나 재시작하지 않았다.

다음 후보는 명시적 이벤트에 기반한 세션 알림이다. AI를 통한 상태 추정이나
정기적인 요약 호출은 도입하지 않는다. 이 단계에는 알림 구현을 포함하지 않았다.

동시 종료 시 남은 파이프 출력 수신을 포함한다. GUI 키 입력 지연·한글 조합은
여전히 별도 검증 대상이다.

## 0.2.1 패키지 검증

[산출물·범위](evidence/session-selector/package-0.2.1.json),
[설치된 패키지 테스트 로그](evidence/session-selector/package-0.2.1.log).
15개 앱 테스트와 6개 로컬 PTY 테스트가 통과했다. 설치 경로의 함수가 사용됐는지
검사했으며, 개인 설정을 읽지 않는 임시 프로필에서 실제 AI 연결 없이 실행했다.
설치·바이트 컴파일·한글 기록 검색·삭제 후 기록 보존도 확인했다.

새 독립 시험 프로필: `bash ~/workspace/emacs-ai/var/package-profile-0.2.1/start.sh`.
준비와 배치 검증은 GUI를 열지 않았다. Computer Use 재시도에서도 native pipe가
시작되지 않아 GUI 긴 후보·completion·한글 조합 검증은 남아 있다.

설치된 패키지 테스트는 처음에 창 수가 항상 1이라는 테스트 가정 때문에 실패했다.
앱은 기존 창 배치를 유지하는 동작이므로, 테스트를 실행 전후 창 수가 동일한지
검사하도록 수정한 뒤 통과했다. 제품 코드로 사용자 창을 강제 정리하지 않는다.
