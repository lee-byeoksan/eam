# 제한된 기록 검색과 페이지 표시

2026-09-09 G06. `Open raw archive` 또는 `emacs-ai-open-transcript`로 연 기록에서 다음을 사용한다.

| 조작 | 동작 |
| --- | --- |
| `/` 또는 AI 메뉴 Search archive | 파일 처음부터 문자열 검색 |
| `M-n` | 마지막 일치 다음 바이트부터 다음 결과 검색 |
| `p` / `n` / `g` | 이전·다음 페이지 / 최신 부분 |
| `c` | 페이지에서 완전한 SGR 색상 코드 숨김·표시 |
| `M-x emacs-ai-history-cancel` | 진행 중 검색 취소 |
| `Q` | 조회 창과 해당 검색 종료, 기록 파일 유지 |

검색 결과 위치 주변만 기존 페이지 상한으로 연다. Emacs의 일반 선택·복사로 내용을 가져갈 수 있다. 검색·표시 과정에서 원본은 쓰지 않고 AI도 호출하지 않는다. 저장 기록의 최신 페이지 헤더는 `ARCHIVE`로 표시해 진행 중 응답과 구분한다.

## 동작 범위

- 별도 Python 프로세스가 64KiB씩 읽으며 검색어 길이-1만큼 겹쳐 검사한다. 따라서 한글·이모지가 청크 경계에 걸려도 찾는다. 전체 파일이나 전체 결과 목록을 메모리에 쌓지 않고 첫 일치의 바이트 위치만 반환한다.
- 검색어는 UTF-8 기준 최대 4096바이트이며 작은 페이지 상한에서는 `상한-8`바이트로 제한해 결과를 페이지 안에 표시한다. 정규식이 아닌 대소문자 구분 리터럴 검색이다.
- 시작 시 파일 크기까지만 검색한다. 검색 중 추가된 출력은 새 검색에서 찾는다. 외부 덮어쓰기·잘림을 일관된 스냅샷으로 보장하지 않으므로 확정된 결과가 필요하면 CLI를 정상 종료한 기록을 사용한다.
- 검색은 비동기이며 취소 또는 조회 버퍼 종료 시 해당 검색 프로세스만 정리한다. 다른 CLI나 다른 창의 검색은 중단하지 않는다.
- 검색 대상은 원시 바이트다. 화면상 같은 단어여도 글자 사이에 ANSI 제어 코드가 끼어 있으면 일치하지 않을 수 있다. 의미 검색·대화 인덱스·ANSI 화면 재생은 구현하지 않았다.
- `c`는 페이지의 완전한 SGR 색상 코드만 제거한 표시다. 커서 이동·화면 지우기·OSC는 실행하거나 재구성하지 않는다. 페이지 경계에 걸린 코드는 조각으로 보일 수 있다. 색상 코드 제거 전 원시 바이트 기준으로 검색하며 원본 복원은 다시 c로 표시한다.

## 검증

`tests/history-test.el`에서 65534바이트 뒤에 한글·이모지 검색어를 배치해 청크 경계 검색, 다음 일치, 128자 페이지 제한, 출력 undo 비활성, 새 검색 시 이전 위치 초기화, 색상 숨김, 조회 종료 시 검색 취소를 확인했다. `scripts/test.sh`에 포함해 일반 버퍼·연결 ERT 총 10개 및 Python 제공자 5개가 통과했다. 최종 헤더/메뉴 변경 뒤 일반 버퍼와 검색 ERT도 재확인했다.

기존 1시간 실험의 `var/terminal-lEsnuq.ansi` 288,352,882바이트에 없는 문자열을 검색했다. 전체 스캔 0.101초, Python tracemalloc peak 201,722바이트. 결과 `var/archive-search-large-20260909.json`. 캐시가 가능한 단일 로컬 실행이며 GUI 지연·전체 RSS·다른 저장장치 성능으로 일반화하지 않는다. GUI에서 직접 검색·스크롤 조작하는 확인은 G01에 남는다.

## 검색 입력 전송 실패 후 정리

2026-09-09 후속: 보조 프로세스 생성 뒤 검색어 전송/EOF 전송에서 오류 또는 quit이 나면 해당 검색 프로세스를 취소하고 원래 오류를 전달하도록 수정했다. 실제 검색 프로세스를 만든 뒤 입력 파이프 오류를 주입해 프로세스 종료·참조 제거·조회 버퍼와 원본 보존을 확인했다. 기존 검색/페이지/취소와 합쳐 ERT 2개 통과. GUI 입력 전달 문제나 서비스 연결 오류를 재현한 것은 아니다.
