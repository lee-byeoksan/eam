# 추가 기능 후보

기록일: 2026-09-10. Paseo, Orca, cmux 검토와 사용자 대화를 바탕으로 정리했다.
후보 목록이며 전체 구현을 확정한 계획은 아니다. 기능을 하나씩 추가하고 검증한다.

## 도입 원칙

- 추가 AI 토큰 소비를 최소화한다. 로컬 정보와 명시적 이벤트로 가능한 기능부터 구현한다.
- 앱의 시스템 프롬프트·스킬·컨텍스트 자동 삽입, 상태 판별용 AI 호출,
  주기적 요약, 요청의 자동 다중 에이전트 배포는 도입하지 않는다.
- 모든 기능을 `M-x` 명령으로 제공하고 자주 쓰는 기능에 키를 매핑한다. GUI 메뉴는 필요 없다.
- 공식 CLI의 직접 입력과 기능을 유지한다. 선택한 내용을 보낼 때는 초안에서 확인하고 명시적으로 전송한다.
- 다른 프로젝트의 개념을 참고하되 포크 기반으로 만들지 않는다.
- 배치 검증과 실제 GUI의 한글 조합·스크롤·반응성 검증을 구분한다.

최종 상태: F01–F07 구현 및 검증 완료, 사용자 시험 설치본 0.8.11.
[요구사항별 완료 근거](completion-audit.md)와 [검증 현황](feature-validation-status.md)을
함께 확인한다. 아래 표의 “이 문서 작성 시 상태”는 순차 구현 당시의 이력이다.

## 기능별 범위와 검증 기준

### F01 — 세션 선택 목록

`M-x emacs-ai-app-switch` / `C-c a s`에서 CLI 종류, 프로젝트 경로,
Git 브랜치, 프로세스 상태를 표시한다. 목록을 열 때 로컬 Git을 프로젝트마다 최대 한 번 조회한다.
동시 실행은 최대 8개, 전체 대기는 기본 2초이며 미완료 조회는 `unverified`로 표시한다.
`process:run`은 프로세스 생존 상태이며 AI의 작업 중·완료·승인 대기를 의미하지 않는다.

남은 확인: 긴 후보 표시, 한글 조합, completion UI 호환성, 많은 프로젝트에서의 지연.
상세 구현·검증·한계는 [세션 선택 기록](session-selector.md)을 따른다.

### F02 — 알림과 해당 세션으로 이동

완료 또는 사용자 확인 요청을 알림 목록에 쌓고 다음 알림의 세션으로 이동한다.
읽음·읽지 않음 상태를 관리하며 macOS 알림은 선택 사항으로 둔다.

공식 CLI 훅이나 터미널 알림 이벤트를 Ghostel에서 받을 수 있는지 먼저 확인한다.
출력 바이트 증가, 침묵, 화면 문자열만으로 완료·승인 대기를 단정하지 않는다.
확인할 수 없는 상태는 미확인으로 표시한다. 이벤트의 의미를 보존하고 자동 승인하지 않는다.

검증: 세션별 이벤트 귀속, 중복 억제, 종료한 세션 처리, 알림 기록의 크기 제한,
키보드 이동, 추가 AI 호출 없음. 제공자별 이벤트 지원 여부는 구현 전에 별도 검증한다.

### F03 — diff 리뷰 의견 전달

Magit·diff-mode 등에서 변경 줄을 선택해 의견을 작성한다.
파일 경로·줄 위치·선택한 diff·의견을 초안에서 확인한 뒤 CLI로 전송한다.
최종 명령 이름과 키는 구현 시 정한다.

전체 파일이나 전체 diff를 자동 첨부하지 않는다. 큰 선택은 분량을 보여주고 줄일 수 있게 한다.
전송할 때만 토큰이 사용되며, 정확한 토큰 수를 로컬 문자 수와 동일시하지 않는다.

검증: 한글 경로, 변경 후 줄 위치, 여러 hunk, 긴 선택의 분량 제어,
취소 시 입력 미전송, 사용자 입력 undo 유지.

### F04 — worktree와 세션 연결

worktree 생성·선택과 해당 디렉터리에서의 CLI 실행을 연결한다.
관련 파일·브랜치·세션으로 빠르게 이동한다. 병렬 AI 요청은 자동으로 시작하지 않는다.

검증: 같은 저장소의 여러 작업 격리, 기존 worktree 연결, 경로 공백·한글,
미커밋 변경 또는 실행 중 세션이 있는 worktree의 삭제 방지.

### F05 — 프로젝트별 실행 명령

테스트·빌드·개발 서버 명령을 사용자가 등록하고 `M-x`에서 선택한다.
Emacs의 compilation 버퍼 등 기존 기능을 활용한다.
프로젝트 진입만으로 명령을 실행하거나 실행 결과를 AI에 자동 전송하지 않는다.

검증: 작업 디렉터리, 종료 코드, 취소, 긴 출력 처리, 프로젝트 간 명령 분리.
사용자가 등록한 명령 자체가 AI를 호출하는 경우까지 토큰 무료를 보장하지는 않는다.

### F06 — 작업 공간 복원

프로젝트, 세션 식별 정보, 창 배치를 저장하고 다음 실행에서 목록을 복원한다.
목록 복원만으로 CLI 실행이나 대화 재개를 자동 수행하지 않는다.
종료한 프로세스와 연결 가능한 프로세스를 구분한다.

검증: 사라진 경로·세션, 중복 복원, 저장 형식 변경, 복원 중 AI 호출 없음.
메타데이터 복원은 실제 실행 중 프로세스의 재접속과 별개다.

### F07 — 독립 프로세스 관리와 재접속

Emacs 밖에서 터미널 프로세스를 유지하고 나중에 다시 연결하는 기능이다.
기존 CLI의 대화 ID 재개와는 다른 기능이며 구현 범위가 크다.

먼저 프로세스 소유권, 명시적 종료 방법, 기록 중복 방지, 버퍼 제한,
재접속 실패 처리를 검토한다. Emacs를 닫아도 AI가 계속 작업하면 토큰은 계속 사용될 수 있다.
후보 작성 시에는 실사용 필요 확인 후 착수하기로 했다. 이후 이 문서의 순차 구현·검증 목표에 따라 기반 실험을 시작했다. [재접속 실험과 남은 구현](persistent-terminal.md)을 따른다.

## 당장 우선하지 않는 후보

- 내장 브라우저와 UI 요소 선택 전송: 범위가 크고 이미지·페이지 첨부로 입력량이 늘 수 있다.
- 모바일·원격 제어: 연결 유지와 인증, 프로세스 수명 관리가 선행되어야 한다.
- 음성 입력: 한글 직접 입력과 초안 편집의 실사용 검증을 먼저 진행한다.
- 사용량·계정 대시보드: 공식적으로 얻을 수 있는 정보의 범위와 유지 비용부터 확인한다.
- 자동 병렬 에이전트 배포·자동 요약: 토큰 최소화 원칙에 맞지 않아 현재 도입하지 않는다.

- [Paseo 저장소](https://github.com/getpaseo/paseo): worktree 실행, 독립 데몬과 클라이언트 연결.
