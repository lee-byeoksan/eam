# 참고 개념과 후속 작업

## 참고 범위

2026-09-08에 공식 저장소의 공개 설명을 확인했다. 코드 복사·포크·의존성 추가 없이 개념만 참고한다.

| 참고 | 확인한 개념 | 이번 실험에 반영한 범위 |
| --- | --- | --- |
| [Orca](https://github.com/stablyai/orca) | 여러 코딩 에이전트를 나란히 관리, worktree 격리 | 세션별 상태·출력 분리만 구현 |
| [Paseo](https://github.com/getpaseo/paseo) | 로컬 daemon이 에이전트를 관리하고 클라이언트가 접근 | UI와 생성기 함수의 경계를 분리; daemon은 만들지 않음 |
| [gptel](https://github.com/karthink/gptel) | Emacs 버퍼 중심 LLM 상호작용과 스트리밍 | 일반 편집 버퍼에서 입력·출력 처리 |
| [claude-code.el](https://github.com/stevemolitor/claude-code.el) | Emacs에서 Claude Code 세션을 다루는 통합 | Emacs 명령·키 바인딩으로 시작/중지 |

Orca는 동명 프로젝트가 많아 `stablyai/orca`를 참고 대상으로 가정했다. 다른 Orca를 뜻했다면 후속 비교 대상을 수정한다. 참고 프로젝트의 구독 지원 설명만으로 우리 연동의 구독 적용을 보장하지 않는다.

## 이번 선택의 검증 기준

가정: 일반 Emacs 입력 버퍼와 제한된 출력 버퍼로 한글 입력감을 유지하면서 여러 세션의 기록을 다룰 수 있다.

출력 누적량과 무관하게 버퍼 문자가 상한을 지키는지는 테스트로 확인했다. 사용자는 GUI 사용에 별 문제가 없다고 보고했다. 이를 세부 IME 항목 전체의 계측 통과로 해석하지 않는다. 동기 디스크 쓰기나 전체 세션 타이머가 GUI를 지속적으로 막는다면, 디스크 writer 분리와 공통 시간 예산을 가진 출력 스케줄러를 다음 실험 대상으로 삼는다. 이를 적용할 때도 대기열 상한과 원본 기록 무손실 조건을 함께 검증해야 한다.

## 실제 연결 단계 결과

공식 문서·현재 구독 로그인 확인과 읽기 전용 연결을 추가했다. Claude·Codex 모두 실제 응답과 같은 대화의 후속 응답을 확인했다. [연결 검증 기록](connections.md)에 인증 조건, 자동 삽입 억제 범위, 호출 횟수와 한계를 기록했다.

이후 사용자의 CLI 기능 보존 요구에 따라 Ghostel 대화형 CLI를 주 실험 방향으로 추가했다. 도구 승인 UI를 새로 만드는 것보다 CLI의 기본 승인을 사용하는 실제 코딩 작업을 먼저 검증한다. 현재 우선순위와 요구사항은 [프로젝트 현황](project-state.md)을 따른다. 초기 프로토타입 성능 수치를 실제 CLI 포함 성능으로 간주하지 않는다.
