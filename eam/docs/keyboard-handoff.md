# 복귀 후 직접 키보드 확인

현재 기본 경로는 **Ghostel 터미널 직접 입력 + 필요할 때 Emacs 편집기**다. 문자열 전달·외부 편집 왕복·한글 경로 검사는 자동으로 확인했다. 남은 것은 **실제 macOS 입력기로 조합하는 동작**이며 Computer Use의 합성 입력으로 이를 대신 검증하지 않는다.

## 지금 필요한 대조 — 열린 일상 앱에서

2026-09-09 최신 검증 대상은 이미 열린 **Emacs AI review** 창이다. 새 창이나 시험 스트림을 열 필요는 없다. 이 창은 개인 Emacs와 별개의 `-Q` 인스턴스이며 현재 시작 화면이다.

1. 이 창에 포커스를 둔 상태에서 macOS 입력 소스를 **ABC**로 바꾸고 전환했다고 알려준다. 이후 Computer Use의 동일 `a` 키·경로 입력은 에이전트가 다시 확인한다.
2. 평소 한글 입력기로 돌아와 아래 실제 CLI의 조합·받침 수정·한영 전환을 직접 확인한다. 읽기 전용 설정 조회에서는 세벌식 390이 선택돼 있었다. 평소 입력기를 두벌식으로 바꿀 필요는 없다.

Computer Use 단일 `a`가 일반 프로젝트 미니버퍼에서도 `ᆼ`으로 변환됐다. 직접 AX 값 설정은 Emacs가 지원하지 않았다. ABC 대조는 자동화 입력 문제를 좁히는 검사이며, 물리 키보드의 한글 조합 통과를 대신하지 않는다. [관찰 기록](daily-gui-validation.md).

사용자 관찰은 입력 소스와 구체적인 차이만 알려주면 된다. 경로·세션 ID 입력, GUI 검색·복사·모드 전환, 부하 중 스크롤/세션 이동과 증거 정리는 입력 전달이 가능해진 뒤 에이전트가 이어서 담당한다. 이미 완료한 1시간 배치 검사를 다시 실행할 필요는 없다.

## 현재 경로: 터미널과 선택적 편집기 — 약 3분

열린 **Emacs AI review**의 `Claude 시작` 또는 `Codex 시작`을 사용한다. 이미 실행된 대화가 있다면 그 입력란에서 확인한다. 다음 스크립트는 별도 Terminal Test 메뉴가 필요한 보조 시험용이며, 열린 일상 앱을 쓰는 경우 실행하지 않는다.

```sh
cd ~/workspace/emacs-ai
bash scripts/terminal-gui.sh
```

새 GUI가 열린다. `Terminal Test → Start Claude CLI` 또는 `Start Codex CLI`로 실제 CLI의 빈 입력란을 연다. 처음 표시되는 가짜 CLI는 직접 누른 모든 글자를 입력란처럼 표시하는 프로그램이 아니므로, 이 조합 검사는 실제 CLI 입력란에서 한다. **아래 시험 문장은 Enter로 제출하지 않는다.**

1. 평소 쓰는 macOS 입력 소스로 `안녕하세요. 값이 바뀝니다.`를 직접 입력한다. `값`의 받침을 조합 중에 Backspace로 지우고 다시 입력한다. 글자 누락·받침 분리·커서 이동을 확인한다.
2. 한/영 전환으로 `abc123`을 넣고 다시 한글로 돌아온다. 문장 중간에서 글자를 수정한다.
3. `Terminal AI → Edit CLI input in Emacs`를 선택한다. 열린 일반 버퍼에 원문이 들어 있는지 확인하고 한글을 수정한다. 일반 버퍼에서 undo로 되돌려 본 뒤 저장하고 `C-x #`로 반환한다. CLI 입력란에 수정본이 그대로 돌아오는지 확인한다.
4. 기존 출력이 있는 대화라면 마우스로 위로 스크롤했다가 입력란으로 돌아와 같은 입력을 해 본다. 이 확인을 위해 새 AI 응답을 요청할 필요는 없다. 출력이 없으면 스크롤 항목은 미확인으로 남긴다.

다른 제공자에서도 차이가 있는지만 확인하면 된다. 종료할 때는 외부 편집기에서 시험 입력을 모두 지우고 저장·반환한 뒤 Claude `/exit`, Codex `/quit`를 사용한다.

메뉴 유지 수정도 새 시험 GUI의 가짜 CLI에서 확인할 수 있다. `Terminal Test → Copy mode` 후 `Terminal AI`가 남는지 보고, 그 메뉴의 `Open draft`가 열리는지 확인한다. `Terminal Test → Return to terminal input`으로 돌아온다. 배치 모드 전환 검사는 통과했지만 Computer Use의 창 조회 오류 때문에 실제 GUI 확인은 남아 있다.

```text
macOS 입력 소스:
Claude 직접 조합/받침 수정/한영 전환:
Codex 직접 조합/받침 수정/한영 전환:
일반 편집 버퍼의 조합/undo/CLI 반환:
스크롤 후 입력: 정상/문제/미확인
구체적으로 달랐던 글자·동작:
```

아래 A/B 비교는 문제가 있을 때 일반 Emacs 입력과 초기 버퍼 구현을 더 분리하는 보조 검사다. 현재 터미널 경로의 필수 준비 단계는 아니다.

## 보조 A/B 비교 준비

별도 `emacs-ai GUI verification` 비교 창은 다음으로 연다.

```sh
bash ~/workspace/emacs-ai/scripts/check-input.sh
```

개인 Emacs 설정을 읽지 않는 별도 앱이다. 상단 **A: plain text-mode**, 중간 **B: prototype input**, 하단 **출력**이 보인다. 기존 시험 내용이 보이면 메뉴 `IME Check → New pair: idle`을 누른다. 이 메뉴는 새 빈 입력 쌍을 만들며 이전 입력은 다른 버퍼에 남긴다.

평소 쓰는 macOS 한글 입력 소스를 이 창에서 직접 선택한다. 두벌식으로 바꿀 필요는 없다. **`Diagnostic paste binding` 메뉴는 누르지 않는다.** 사용자 확인용 화면에는 진단 매핑이 적용되지 않는다.

## 1. 출력이 없는 상태

A와 B에 각각 같은 동작을 한다.

1. **직접 키보드로** `안녕하세요. 값이 바뀝니다.`를 입력한다. `값`을 조합하는 도중 Backspace로 받침을 지웠다가 다시 입력해 본다.
2. 한/영 전환 후 `abc123`을 입력하고 다시 한글로 돌아온다. 커서를 문장 중간으로 옮겨 한 글자를 추가한다.
3. 평소의 undo 키로 추가한 글자를 되돌린다. 필요하면 `Edit → Undo`와 비교한다.
4. 위 문장을 직접 복사한 뒤 `Command+V`로 붙여넣는다. 실패하면 `Edit → Paste`도 시험하여 키와 메뉴의 차이를 알려준다.

완료하면 **`IME Check → Capture both inputs`**를 누른다. A/B의 입력 내용과 최근 최대 100개 명령 이벤트가 프로젝트 `var/ime-comparison.jsonl`에 기록된다. 이 두 테스트 버퍼만 기록하므로 시험 문장을 사용하면 된다.

## 2. 출력이 있는 상태

`IME Check → New pair: 12 streams`를 누르면 새 A/B 쌍과 약 2분짜리 가짜 스트림 12개가 시작된다. 실제 AI 호출은 없다.

A와 B에서 위의 한글 조합·수정·undo를 반복한다. 하단 로그도 위로 스크롤한다. 멈칫함, 글자 누락, 조합 분리, 포커스 이동이 생기는지 비교한다. 하단 `AI → Previous page`로 고정한 기록은 새 출력이 와도 움직이지 않아야 한다.

다시 `IME Check → Capture both inputs`를 누르고 **`IME Check → Stop background streams`**로 끝낸다. 자동으로도 약 2분 뒤 종료된다.

## 알려줄 내용

다음 정도면 원인을 다음 단계로 좁힐 수 있다. 두 모드가 다를 때는 어떤 글자·동작에서 갈렸는지를 우선 알려준다.

```text
macOS 입력 소스:
무부하: A 정상/문제, B 정상/문제
12개 출력: A 정상/문제, B 정상/문제
Command+V / Edit→Paste 차이:
누락·조합·undo·지연이 있었던 구체적 동작:
Capture both inputs 저장: 완료/미완료
```

## 이미 확인한 것

- live 헤더의 저장 바이트와 출력 문자 수 갱신 수정, 회귀 테스트 통과.
- 0/1/12 스트림에서 동일한 개별 키와 Backspace 결과가 A/B에서 일치.
- 0/12 스트림에서 짧은 연속 키 입력도 A/B에서 일치.
- 자동 완성형 한글 타이핑은 TextEdit에서도 누락됨.
- Emacs 붙여넣기 실패에는 자동 도구가 보낸 잘못된 단축키와 완료 감지 문제가 관여함. 제품에 임시 키 매핑을 넣지 않음.
- 기록 무손실·출력 상한·페이지 이동·입력 undo 보존·출력 undo 비활성 검증 완료.

이 결과만으로 실제 키보드 IME 사용성을 통과 처리하지 않는다.
